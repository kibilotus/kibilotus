# 1단계: 토스 출석 자동화 메커니즘 검증 & 코어 로직

## 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 접근 방식 | A. GUI 제어 (패킷/API 분석 X) |
| 구동 환경 | 폰 단독 네이티브 앱 (Kotlin, AccessibilityService) |
| 기기 | Android 메인 폰 (실기기) |
| 토스 앱 잠금 | 해제 (PIN 자동입력 없음, 금융 비밀번호 저장 없음) |
| 미션 범위 | 매일 출석체크, 버튼 누르고 포인트 받기 |
| 알림 | 3단계에서 인터페이스로 추상화, 텔레그램 먼저 |

## 구조

```
apptech-autopilot/
├─ core/   순수 Kotlin (Android 의존 없음, JVM 단위 테스트)
│  ├─ UiNode / Selector   화면 트리 스냅샷과 요소 검색 조건
│  ├─ Driver / Clock      기기 제어 추상화
│  ├─ Step / Mission      선언형 미션 시나리오
│  ├─ MissionRunner       실행 엔진 (폴링, 차단 감지, 랜덤 탭 좌표/지연, 결과 변환)
│  └─ toss/TossMissions   토스 미션 정의 ← 실기기 보정 대상
└─ app/    Android 앱
   ├─ AutomationService   접근성 서비스 (토스 패키지 이벤트만 수신)
   ├─ AccessibilityDriver Driver 구현 (제스처 탭 → ACTION_CLICK 폴백, 스크롤)
   ├─ UiDumper            셀렉터 보정용 화면 트리 덤프 (4자리 이상 숫자 마스킹)
   └─ MainActivity        설정/상태 화면 (권한, 덤프, 지금 실행/중지)
```

### 실행 엔진 동작
- 미션은 `Launch → 팝업 닫기 → 혜택 탭 → 스크롤 → 진입 → 완료 여부 확인 → 버튼 → 성공 문구 확인 → 포인트 읽기` 순서의 **선언형 단계**로 정의된다. 토스 UI가 바뀌면 `TossMissions.kt`의 문구만 고치면 된다.
- 앱은 `FLAG_ACTIVITY_CLEAR_TASK`로 항상 첫 화면부터 시작한다. 이전에 보던 화면에 상관없이 같은 경로를 탄다.
- 결과 상태
  - `SUCCESS`: 완료
  - `ALREADY_DONE`: 오늘 이미 완료해서 스킵
  - `FAILED`: 재시도 대상
  - `BLOCKED`: 사람이 조치해야 함 (앱 잠금, 자동화 경고)
- 실패하면 실패한 단계, 사유 코드, 실패 시점 화면 트리를 결과에 담는다. 3단계에서 DB에 저장한다.
- 탭은 요소 영역 안쪽 60% 범위의 랜덤 좌표에서 40~120ms 동안 누르고, 동작 사이에는 0.5~1.4초 랜덤 대기를 둔다. 스케줄 단위의 1~5분 지터는 2단계에서 넣는다.

## 스크린샷으로 보정한 내용 (2026-10-13)
- 하단 탭: 홈 / 혜택 / 쇼핑 / 증권 / 전체
- **출석체크**: 증권 탭 → "맞춤형 서비스" 목록 → "출석체크하고 적립금 받기"
  - 이 목록은 "다른 서비스 더 보기 1/2"로 넘어가며 바뀝니다. 출석체크 항목이 안 보이면 넘겨서 찾도록 했습니다.
- **버튼 누르기**: 혜택 탭 → "버튼 누르기" → "매일 버튼 누르고 8번 포인트를 받아요" → "쿠팡에서 N원 받기"
  - 3시간 회차로 하루 8번입니다. 보상 버튼이 없으면 이번 회차는 받은 것으로 처리합니다.
  - 버튼을 누르면 쿠팡으로 넘어갑니다. 6~12초 머문 뒤 뒤로가기로 토스에 돌아오고, 보상 버튼이 사라졌는지로 지급을 확인합니다.
- 토스는 화면 캡처를 막지 않습니다. 덤프할 때 스크린샷도 남습니다.
- **아직 필요한 것**: 출석체크 화면 내부(출석 전/후), 쿠팡에서 돌아온 뒤 화면, 그리고 앱 덤프 기능으로 뽑은 접근성 트리 (text/desc/클릭 가능 구조 확인용)

## 실기기 검증 절차 (사용자 작업)

> 현재 `TossMissions.kt`의 문구(셀렉터)는 **추정값**입니다. 아래 절차로 받은 덤프로 제가 보정합니다.

1. **빌드/설치**: Android Studio에서 `apptech-autopilot/` 폴더를 열고 `app`을 메인 폰에 설치합니다.
2. **제한된 설정 허용** (Android 13 이상, APK 직접 설치 시): 설정 → 애플리케이션 → 앱테크 오토파일럿 → 우측 상단 ⋮ → **제한된 설정 허용**
3. **접근성 서비스 켜기**: 앱의 "접근성 서비스 설정" 버튼 → 설치된 앱 → 앱테크 오토파일럿 → 사용
4. **토스 반응 확인 ★가장 중요**: 접근성 서비스를 켠 상태로 토스를 실행했을 때
   - 원격제어/접근성 경고 팝업이 뜨는지
   - 앱이 종료되거나 기능이 막히는지
   - → 막힌다면 폰 단독 방식은 불가하고 PC+ADB 방식으로 전환을 논의해야 합니다.
5. **화면 덤프 수집**: "10초 후 화면 덤프" 버튼을 누르고 10초 안에 토스의 아래 화면으로 이동합니다. 화면마다 반복하고, 각각 "덤프 공유"로 보내 주세요.
   - (a) 토스 첫 화면(홈)
   - (b) 혜택 탭 (버튼 누르기 항목이 보이는 상태)
   - (c) 증권 탭의 "출석체크하고 적립금 받기" 목록과 출석체크 화면 (출석 전, 가능하면 출석 후도)
   - (d) 버튼 누르기 화면 (누르기 전, 쿠팡에서 돌아온 직후)
6. **(선택) 시험 실행**: "미완료 미션 지금 실행" 버튼. 아직 보정 전이라 실패해도 괜찮습니다. 실패 덤프는 `Android/data/com.kibilotus.apptech/files/dumps/`에 저장됩니다.

### 덤프 개인정보
- 덤프에는 토스 화면의 텍스트가 들어갑니다. 4자리 이상 숫자(잔액, 계좌번호 등)는 `####`로 자동 마스킹되지만, **이름 등은 남을 수 있으니** 공유 전에 확인해 주세요.

## 알려진 위험
- **약관**: 자동화는 토스 이용약관상 제재 대상이 될 수 있습니다 (포인트 회수, 이용 제한).
- **보안 앱 탐지**: 금융 앱이 접근성 서비스를 탐지해 막을 수 있습니다. 검증 4번 항목에서 확인합니다.
- **WebView 화면**: 혜택 페이지가 WebView라면 텍스트가 `contentDescription`에만 있을 수 있습니다. `Selector`는 text와 desc를 모두 검사합니다.
