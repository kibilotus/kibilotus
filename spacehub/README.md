# SpaceHub: 공간대여 예약 통합관리 (스튜디오버디 전용)

네이버 예약, 스페이스클라우드, 직접 예약을 한곳에 모으고, 예약에 맞춰 카카오 알림톡을 자동으로 보냅니다.
한 업체가 쓰는 단일 서버 구성입니다.

## 동작 방식

```
[5분마다]
  예약 수집 ─ 네이버 예약 알림 메일 (IMAP)           ┐
            ─ 스페이스클라우드 (구글 캘린더 구독)     ┼→ 통합 예약 DB (SQLite) → 알림톡 규칙 판정 → 솔라피 발송
            ─ 직접 예약 (관리 화면 / 구글 캘린더)     ┘        │
                                                      중복 예약 감지, 마감용 캘린더 주소 제공
```

- **네이버 예약, 스페이스클라우드**: 공개 API 가 없어서 사업자에게 오는 **예약 알림 메일**을 읽습니다. 예약번호로 신규·취소를 맞춥니다.
- **스페이스클라우드**: 호스트센터의 캘린더 내보내기 주소를 구글 캘린더에 구독해 두고 그 캘린더를 읽습니다. 일정 변경과 취소(목록에서 사라짐)도 반영합니다. 구글은 구독 캘린더를 몇 시간마다 다시 받아오므로 그만큼 늦게 반영됩니다. 더 빨라야 하면 같은 주소를 직접 읽는 `spacecloud_ical` 로 바꿀 수 있고, 예약 ID 가 같아 중복 없이 이어집니다.
- **중복 예약**: 같은 공간에서 시간이 겹치는 확정 예약을 대시보드에 표시합니다.
- **마감용 캘린더 주소** (`/feed/<feed_token>.ics`): 모든 확정 예약을 개인정보 없이 '예약됨'으로 내보냅니다. 외부 캘린더를 받아주는 채널에 등록하면 시간이 막힙니다.
- **알림톡**: 예약 등록 즉시, 이용 전날 HH:MM, 이용 시작/종료 N분 전, 예약 취소 시. 채널별로 다르게 적용할 수 있고, 같은 메시지는 한 번만 보냅니다. 일시 오류는 최대 3번 다시 시도합니다. 발송 금지 시간(`quiet_hours`, 기본 22:00-08:00)에 걸린 메시지는 금지 시간이 끝난 뒤 보냅니다.

## 실행

```bash
cd spacehub
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp config.example.yaml config.yaml          # 공간, 메일 계정, 알림 규칙 수정

export ADMIN_PASSWORD='관리 화면 비밀번호'     # 아이디는 admin
export IMAP_PASSWORD='Gmail 앱 비밀번호'
export SOLAPI_API_KEY=... SOLAPI_API_SECRET=... SOLAPI_PF_ID=... SOLAPI_SENDER=021234567

python -m app.main seed     # 최초 1회: 기존 예약을 가져오되 지금 발송 대상에는 보내지 않음
python -m app.main serve    # 관리 화면 http://127.0.0.1:8000 + 5분마다 동기화/발송
```

처음에는 `dry_run: true` 로 두고 발송 내역 화면에서 결과를 확인한 뒤 `false` 로 바꾸세요.
외부에서 접속하려면 HTTPS 리버스 프록시(Caddy, Nginx 등) 뒤에 두고 `--host 0.0.0.0` 으로 실행합니다.

## 네이버 예약 (알림 메일 + 직접 보내기)

네이버 예약 알림 메일에는 **전화번호가 없고 예약자명도 가려져 있습니다** (예: `최*정님`). 그래서 두 가지 메일을 예약번호로 합칩니다.

1. **네이버 예약 알림 메일**: 예약번호, 상품, 이용일시, 결제금액. Gmail 로 들어오게 해 두면 자동으로 읽습니다.
   이용일시에 날짜만 있으면 상품명(`11시 - 17시`)이나 결제금액 옵션(`체크아웃시간 동일[12시-24시]`)의 시간을 씁니다.
2. **사장님이 보내는 예약 상세**: 스마트플레이스 앱의 **예약 상세정보** 화면 내용을 복사해 Gmail 로 보냅니다 (`forwarders` 에 적은 주소에서).
   예약번호가 같으면 **전화번호와 전체 이름이 채워지고**, 그때 예약완료 알림톡이 나갑니다.
   알림 메일을 그대로 전달(Fwd)해도 됩니다. 제목이나 본문에 '스페이스클라우드'가 있으면 스페이스클라우드 예약으로 읽습니다.

전화번호가 들어오기 전까지 알림톡은 **연락처 대기** 상태로 기다리고, 이용이 끝나면 대상에서 빠집니다.

## 스페이스클라우드 연동 (구글 캘린더 구독)

1. **스페이스클라우드 주소 복사**: 호스트센터 → 예약 리스트 → 캘린더 보기 → 캘린더 내보내기 → 복사
2. **구글 캘린더에 구독**: 구글 캘린더(PC) 왼쪽 '다른 캘린더' 옆 `+` → **URL로 추가** → 주소 붙여넣기
3. **구글 로그인 준비 (최초 1회)** — [Google Cloud 콘솔](https://console.cloud.google.com/)에서
   - 프로젝트 만들기 → **Google Calendar API** 사용 설정
   - **OAuth 동의 화면**: 사용자 유형 '외부', 테스트 사용자에 사장님 구글 계정 추가 후 **앱 게시(프로덕션)**로 전환
     (테스트 상태로 두면 로그인이 7일마다 풀립니다. 검증 전이라 로그인 때 '확인되지 않은 앱' 경고가 나오는데, 본인 앱이므로 계속하면 됩니다)
   - **사용자 인증 정보 → OAuth 클라이언트 ID → 데스크톱 앱** 만들고 JSON 을 `client_secret.json` 으로 저장
4. **로그인 (브라우저가 있는 PC에서)**
   ```bash
   python -m app.main google-login      # 브라우저가 열리면 사장님 계정으로 로그인
   ```
   `google-token.json` 이 만들어지고, 읽을 수 있는 캘린더 목록이 나옵니다. `@import.calendar.google.com` 으로 끝나는 것이 구독한 스페이스클라우드 캘린더입니다.
5. `config.yaml` 의 `sources.google_calendars` 에서 `spacecloud_gcal` 의 `calendar_id` 를 넣고 `enabled: true`
6. 서버에서 실행한다면 `google-token.json` 을 서버의 `spacehub` 폴더에 올립니다. (비밀번호처럼 다루세요)

## 관리 화면

| 화면 | 내용 |
|---|---|
| 대시보드 | 오늘 공간별 예약, 이번 주 매출·알림톡, 확인 필요(중복 예약, 연락처 없음, 발송 실패, 읽지 못한 메일) |
| 통합 캘린더 | 주간 보기, 채널 필터, 겹치는 예약 표시 |
| 예약 목록 | 30일 예약과 알림톡 발송 상태, 직접 예약 추가·취소 |
| 채널 연동 | 채널별 동기화 상태, 마감용 캘린더 주소 |
| 자동 알림톡 | 규칙 켜기/끄기, 발송 시점, 적용 채널, 문구, 템플릿 ID, 미리보기 |
| 발송 내역 | 최근 100건 |

## 코드 구조

| 파일 | 역할 |
|---|---|
| `app/sources/email_source.py` | IMAP 메일 읽기, 예약 메일 해석 (라벨은 config 에서 변경 가능) |
| `app/sources/ical_source.py` | 캘린더 주소(.ics) 읽기 |
| `app/sources/gcal_source.py`, `app/calendar_client.py` | 구글 캘린더 읽기 (스페이스클라우드 구독, 직접 예약) |
| `app/sources/event_parse.py` | 캘린더 일정 → 예약 (iCal, 구글 공통) |
| `app/sources/text.py` | 이용일시·금액·라벨 해석 |
| `app/db.py` | 통합 예약, 발송 이력, 규칙, 동기화 상태 (SQLite) |
| `app/sync.py` | 소스 → DB 반영, 사라진 예약 취소 처리 |
| `app/scheduler.py` | 발송 시점 계산, 중복 방지 키 |
| `app/notifier.py` | 알림톡 발송 판정·재시도 |
| `app/sender.py` | 솔라피 API, 테스트 모드 |
| `app/web.py`, `app/static/index.html` | 관리 API, 관리 화면, 마감용 피드 |
| `app/engine.py`, `app/main.py` | 주기 실행, 진입점 |

## 알려진 한계

- 예약 알림 메일 양식은 실제 메일 샘플 없이 일반적인 형태로 가정했습니다. 샘플을 받으면 `tests/test_sources.py` 에 추가하고 라벨을 맞춰야 합니다.
- 네이버 예약은 외부에서 시간을 막을 방법이 없어 중복 예약 경고까지만 합니다.
- 결제 연동, 직접 예약용 고객 페이지는 아직 없습니다 (관리자가 입력).
